# Catnip architecture

How the code is organised, so a new session can start a feature without reading every file. For *why* things work this way under Midnight's combat restrictions, see [api-research.md](api-research.md). For what to build, see [design.md](design.md).

## Files (load order, from `Catnip.toc`)

| File | Owns |
|------|------|
| `Catnip.lua` | Core: the HUD frame (`ns.hud`, 240×240), shared sizes, saved settings, slash commands, debug helpers |
| `Profiler.lua` | `/catnip perf`: times Catnip's own code. `ns.Profiled(module)` returns a `CreateFrame` and `C_Timer` for that module; every runtime file starts with `local CreateFrame[, C_Timer] = ns.Profiled("<File>")`, so its plain frames (type `Frame`, no template) time each script they run (OnEvent keyed by event name) and its timer callbacks are timed too. Off, a wrapper only checks a flag. Reports ms of our code per second of play, in and out of combat, plus Blizzard's `C_AddOnProfiler` numbers if the client has them; saved in `CatnipDB.perfReports` (last 10). Loads right after Catnip.lua, before every file it times. The settings window, Edit Mode and AddOns page files aren't timed (they only run while open) |
| `SpellTiming.lua` | What we know about spell timing, shared by the GCD pie, the cooldown arcs and rings, and the cooldown box: `ns.GCD_SPELL`, `ns.ReadCooldown`, `ns.GcdRunning`, `ns.CooldownState`, and learned lengths (`ns.LearnedLength`/`ns.LearnLength`, per character in `ns.char.lengths.cooldown`/`.gcd` by spell name, rounded to 0.5s). Moves the old per-arc keys (`spLength`…) and `gcdLengths` into it on load |
| `Elements.lua` | The element registry for customisation ([settings-plan.md](settings-plan.md)): `ns.ZONES` (the settings window's zones after General: Above, Circle, Below, each listing elements in `groups` by the elements' `zone` field, a named group getting a heading), `ns.RegisterElement`, `ns.GetElement`, `ns.ElementOption` / `ns.ElementStored` / `ns.SetElementOption` / `ns.ResetElement` / `ns.ResetAllElements`, stored in `CatnipDB.elements[id][key]` (nil = default, or General's value for an `inherit` option; shared across Edit Mode layouts). Every element's `apply(get)` runs on load and after any change. Also the font helpers: `ns.FONTS` (Blizzard fonts only), `ns.OUTLINES`, `ns.ApplyFont(fontString, font, size, outline)` (falls back to the standard font if a file doesn't load), `ns.FontObject(font, size)` (a cached Font object, for text that refuses `SetFont`, like Blizzard's menu labels), `ns.TextOptions(defaultSize)`, and the `general` element (font, outline). An element's optional `order` sorts it within its group in the settings list (the combo rings use their dot's number); `glyph` (`{ kind = "disc" | "ring" | "arc" | "dots" | "text", color = { r, g, b } }`) its icon. An option may have `get`/`set` (stored elsewhere, e.g. on a combo ring's ability) and `enabled` (a function; the choice control dims and ignores the mouse while false); an element may have `onReset` (before Reset to defaults). `hidden = true` keeps an element's code and options but doesn't offer it: not listed in the settings, not outlined in preview mode, and stored values ignored (defaults only); hidden since 2026-10-08: Resource circle, Mana prediction, Five-second ring, GCD pie, Enrage tint, Maul orb; since 2026-10-09 the Shifting Power and Growl arcs (`under.sp`, `under.growl`, kept for their samples) are offered as one element, `under.arc` "Cooldown Arc" (GrowlArc.lua: Shifting Power and Growl switches, an arc switched off never showing so the other has the spot in every form (its clock still runs; `ns.SetShiftingPowerArcEnabled` also stops the ready pulse), one Opacity for whichever arc shows, via `ns.SetShiftingPowerArcOpacity`, plus Shifting Power's ready pulse, read by ShiftingPower.lua). Likewise the swing time and the cast time and name are one element, `text.under` "Swing/Cast Timer" (Cast.lua: Timer size for both times, Spell name size; `text.swing` and `text.castTime` kept, hidden, for their samples; `text.castName` removed). Options can be `hidden` too (control not shown, stored value ignored): font and outline on every text element, and the `general` element (their shared defaults) as a whole, since 2026-10-09; text elements offer only Size. Its optional `hit` shape (`{ kind = "circle", radius, x, y }` in HUD units from the centre, or `{ kind = "ring", inner, outer, angle, spread }`, a band round the centre, optionally only within `spread` of maths angle `angle` (6 o'clock is -pi/2; the outline is cut to it with two `half_plane` masks); `{ kind = "circles", radius, centres = fn }`, several circles picked and outlined as one (the shift orbs); circles and rings may have `visible = fn`; or `{ kind = "text", region, anchor, point, y, chars, below }`: a box of our own at the text's anchor, sized from its Size option (`size`) plus `below` (a second line's height); any of region, anchor, y, chars and below may be a function, read each refresh, since a FontString showing a secret value has a secret rect) makes it pickable in preview mode. `sample(state)` draws a preview sample state (nil: back to the real one). Opening a page or changing an option never switches the preview's form or stealth: only the settings window's buttons do (the `states` and `stealth` fields that did were removed, 2026-10-08). Loads right after Catnip.lua so modules can register at file load |
| `Preview.lua` | `ns.Preview`: preview mode, on while the settings window shows the Rotation tab (`SetWanted`), out of combat and outside Edit Mode (Blizzard's or Catnip's, polled every 0.25s). On a layer at hud +30 (ignores the HUD's opacity): every element with a `hit` gets an outline (circle: `circle_feather` + `ring_thin` tinted blue; ring: `ring_bar` sized to the band plus `ring_thin` at both edges; text: Edit Mode's nine-slice via `ns.ApplyEditModeLook` on the text's box), faint when idle, bright when hovered on the HUD or in the settings tree (`SetListHover`), yellow/gold when its page is open (`SetSelected`). One catcher frame over the HUD hit-tests the cursor against the shapes each frame (texts first, then circles and rings by how far out they reach); it takes the mouse only while over an element, so the world stays clickable elsewhere. Hover shows a tooltip; a click calls `ns.OpenElementSettings`. While active the HUD always shows a sample state (`Preview.STATES`: caster (shows a spell being cast), bear, cat, plus a Stealth toggle (`GetStealthed`, `SetStealthed`, `CanStealth`: Cat and Caster) that sets `ns.SetStealthPreview` before the samples run, so swing and cast samples skip while stealthed; starts at the player's current one; a row of buttons at the top of the settings list (`short` labels), `GetState`/`SetState`, `onStateChanged`): every element's `sample(state)`, plus `ns.SetStealthPreview` (true for prowl, false otherwise, nil when it ends). Samples so far: Resource.lua (energy 70/100, rage 45, mana 80% of the real max), Swing.lua (a 2.5s swing looping on the ring and text in cat and bear; real swings noted but not drawn), Cast.lua (in caster, a 2.5s Regrowth looping on the arcs and time text; real cast events ignored, re-read when it ends). While the resource circle shows a sample (`ns.IsResourceSampled()`), ManaPrediction.lua hides its bands (a real cast during a Bear preview showed them over the rage fill, 2026-10-04) |
| `UnlockOverlay.lua` | `ns.CreateUnlockOverlay(parent, name, onClick)`: the unlock-mode overlay for the HUD and the cooldown box, styled like Blizzard's Edit Mode (`editmode-actionbar-highlight` nine-slice via `NineSliceUtil.ApplyLayout`, flat blue tint if the atlas is missing). On hover an additive copy of the art brightens it (`HOVER_GLOW`), "Click To Edit" shows in the middle, and a gold name tag (`name`: "Rotation Frame", "Cooldown Frame") pokes out of the right edge. A click that isn't a drag (cursor moved ≤ 4px) calls `onClick`. Also exports `ns.ApplyEditModeLook(frame, selected)` (Edit Mode's blue nine-slice, or its yellow `editmode-actionbar-selected` kit; flat tint fallback) for Preview.lua |
| `Layout.lua` | Moving/resizing the HUD: unlock mode (drag; click opens its settings); the HUD frame's height (what both Edit Modes outline) is at least 240 and grows evenly to reach its lowest text, `ns.SetHudTextBottom` (Cast.lua: timer and spell name sizes below `TIME_TEXT_OFFSET`; out of combat only, applied after combat); `ns.SetHudScale`, `ns.SetHudAlpha` (`hudAlpha`, default 0.95, min `ns.MIN_ALPHA` 0.1; the whole HUD inherits it), `ns.SetHudPosition`, `ns.SetHudUnlocked`, `ns.IsHudUnlocked`, `ns.ResetHudPosition`, `ns.SetHudEnabled` (`hudEnabled`, the settings window's Rotation Frame switch), `ns.ResetHudLook` (scale, opacity and on/off back to their defaults; not position); the `stealth` element (Stealth Mode, under General: Enabled turns stealth's whole look on or off via `ns.SetStealthModeEnabled` in Stealth.lua, which makes `ns.IsStealthMode()` false while off; the HUD's alpha is Overall opacity times its share while `ns.IsStealthMode()`, reapplied on `ns.OnStealthChanged`) |
| `ActionBar.lua` | "Hide Action Bar 1" / "Hide Stance Bar" settings (`hideActionBar1`, `hideStanceBar`; `ns.UpdateBlizzardBars`): `MainActionBar` / `StanceBar` at alpha 0 (re-applied by a `Show` hook installed on first use) plus mouse off on the bar, its buttons (`ActionButton1-12`, `StanceButton1-10`) and the page arrows (out of combat only). Never `Hide()`/`SetParent`: EllesmereUI found those taint Blizzard's action bar code. Keybinds keep working |
| `VehicleLeaveButton.lua` | Blizzard bug workaround: hooks `TakeTaxiNode` and, when the chosen route has more than one hop (`GetNumRoutes`), calls `MainMenuBarVehicleLeaveButton:Update()` then and on `PLAYER_CONTROL_LOST/GAINED`, then once a second until the flight ends, so the "request early landing" button shows on flights with a connection to get off at. Direct flights leave it hidden. Out of combat only (Edit Mode frame) |
| `EditMode.lua` | Catnip Edit Mode panel, the fallback when Blizzard's Edit Mode can't be used (BlizzardEditMode.lua), styled like Blizzard's "HUD Edit Mode" dialog with stock textures/templates (dialog border, `UIPanelButtonTemplate`, `UIPanelCloseButton`). Shown exactly while unlocked (`ns.IsHudUnlocked`); closing it locks. Only moves the frames: a hint, Reset Positions (position only) and Done; `ns.OpenEditMode()` |
| `EditModeSnap.lua` | `ns.EditModeSnapOffset(frame, selections)`: snapping on drop for LibEditMode frames, which the library lacks. Only reads Blizzard's frames; never calls Edit Mode code. One-way: Blizzard's frames don't snap to ours (that would mean registering in Blizzard's magnetism table). |
| `BlizzardEditMode.lua` | Catnip's frames in **Blizzard's** Edit Mode via LibEditMode (`ns.LibEditMode`): the HUD and the cooldown box get Blizzard's selection box and drag (with snapping, EditModeSnap.lua). On/off, scale, opacity and size live only in the settings window (decided 2026-10-08, to keep each setting in one place). Moves save to `CatnipDB` as centre offsets, one position per frame whichever Blizzard layout is active (per-layout copies were removed 2026-10-08 as too complicated; `CatnipDB.layouts` is cleared on load). The HUD's default for Reset Position is kept divided by its scale, since the library anchors it in the HUD's own units. While Edit Mode is open, `ns.Cooldowns.SetPreview(true)` shows every tracked cooldown icon. Selecting a frame calls `ns.FollowSettings` (Options.lua), which turns an open settings window to that frame's tab. Replaces `ns.OpenEditMode` with opening Blizzard's Edit Mode. Does nothing (EditMode.lua stays in charge) if the library or `EditModeManagerFrame` is missing |
| `CooldownManager.lua` | `ns.CDM`: reads Blizzard's Cooldown Manager frames. Now only the Clearcasting fallback uses it; also `/catnip cdm` |
| `AuraContainer.lua` | `ns.CreateAuraContainer`: shared setup for Blizzard's AuraContainer (how we show auras in combat) |
| `Stealth.lua` | Stealth mode state: `ns.IsStealthMode()`, `ns.OnStealthChanged(fn(stealthed))`. ## Shared namespace (`local addonName, ns = ...`)

**Core (`Catnip.lua`)**
- `ns.hud`: the frame everything draws in. Layout.lua positions and scales it.
- Sizes: `ns.RESOURCE_SIZE` (100), `ns.SWING_RING_SIZE` (134), `ns.TIME_TEXT_OFFSET` (104: top of the cast and swing time text, below the HUD centre). `ns.MEDIA`: texture folder path.
- `ns.db`: saved settings (`CatnipDB`), ready inside `ns.OnLoad` callbacks. Modules add defaults to `ns.defaults` at file load.
- `ns.char`: this character's settings (`CatnipDB.chars[<player GUID>]`, with a `name` field to tell them apart in the saved file), ready inside `ns.OnCharacterLoad` callbacks (`PLAYER_LOGIN`), not `ns.OnLoad`. Keyed by GUID because `UnitName` returns the account-wide first name, the same for every character (2026-10-08). Event handlers that use it must return early while it is nil (`SPELLS_CHANGED` can come before `PLAYER_LOGIN`). For what depends on the character's spells and talents: the tracked cooldowns (`cdTracked`), `cdLastPotion` and learned `lengths`. To make another key per-character, add it to `CHARACTER_KEYS` in `Catnip.lua` (which moves an old account-wide value to the first character that logs in) and read it from `ns.char`. Everything else is account-wide.
- `ns.OnLoad(fn)`: run `fn` once saved settings are loaded (`ADDON_LOADED`).
- `ns.SettingsChanged()` after changing a setting; `ns.OnSettingsChanged(fn)` to react (the settings window refreshes on it). To add a setting for a HUD element (its look: opacity, text, formats), add an option to its `ns.RegisterElement` spec in the owning module and handle it in `apply`; the Rotation tab builds the control. Other settings: default in `ns.defaults`, an apply function in the owning module, a control in `Options.lua`.
- `ns.commands.<name> = fn(arg)`: adds `/catnip <name> <arg>`. `ns.commands[""]` is plain `/catnip`. Update the help text in `Catnip.lua` when adding one.
- `ns.Print(...)`, `ns.Debug(...)` (only with `/catnip debug` on; secret-safe), `ns.Describe(v)`, `ns.IsSecret(v)`.
- `ns.TryRegisterEvent(frame, event)`: registers an event that may not exist in this client; returns success.
- `ns.FindKnownSpell(names)`: ID of the first of `names` in the spellbook (`C_Spell.GetSpellInfo` by name, then `IsPlayerSpell`), else nil.

**Spell timing** (SpellTiming.lua; loads right after Catnip.lua, so usable anywhere)
- `ns.GCD_SPELL` (29515): the spell Forever reports the GCD on. `ns.GcdRunning()`: from the readable `isActive`.
- `ns.ReadCooldown(spellID)`: `start, duration` when readable (out of combat), else nil; duration 0 when not on cooldown.
- `ns.CooldownState(spellID, previous)`: `onCooldown, sure` for a real cooldown (not the GCD) from the readable `isActive`/`isOnGCD` flags; `previous` comes back when it can't tell. Used by Cooldowns.lua and SegmentedCooldown.lua.
- `ns.LearnedLength(kind, name)` / `ns.LearnLength(kind, name, seconds)`: lengths learned from casts, `kind` `"cooldown"` or `"gcd"`, by spell name. For anything running its own clock (secret timing in combat). Not for the cooldown box: its duration objects are exact.

**Features**
- `ns.CreateAuraContainer{ label, unit, filter, spellIDs, width, height, x, y, relativeTo, level, parent, initialize }` and `ns.HideAuraButtonArt(button)` (AuraContainer.lua). `ns.HAS_AURA_CONTAINER`. Position and level are relative to `relativeTo` (default the HUD). Containers made after login are created immediately (out of combat). Returns a handle whose `SetSpellIDs(list)` changes the matched auras later.
- `ns.Cooldowns.Candidates()`, `.IsTracked(id)`, `.SetTracked(id, bool)`, `.Move(from, to)`, `.ResetPosition()`, `.ResetLayout()` (every `DEFAULTS` key: size, position, icon size, overflow, opacity, alignment, on/off; not the tracked list), `.SetEnabled(bool)` (`cdEnabled`, the Cooldown tab's Cooldown Frame switch), `.SetLayout(x, y, w, h)`, `.SetAlignment(point)`, `.SetAlpha(a)` (Inactive opacity: `cdAlpha` on the box, default 1), `.SetIconSize(n)` (`cdIconSize`, default 40: icons no longer fit to the box; its width sets how many go in a row), `.SetOverflow(mode)` (`cdOverflow`: "hide" or "spill"; `Arrange` shows the icons it places and hides overflow, `Update` only sets each slot's `showWanted`), `.SetActiveAlpha(a)` (Active opacity: `cdActiveAlpha`, default 1, on each icon's `activeGate`, a frame of ours holding its AuraContainers and ignoring the box's alpha, since the styled buttons can't be changed; the samples' `active` frame likewise) (Cooldowns.lua). Special-case potions in `cdPotionItems`, the last potion used in `cdLastPotion`; box layout in `cdX`, `cdY`, `cdWidth`, `cdHeight`; learned buffs in `cdBuffs` (ability name → buff spell ID).
- `ns.comboGroup`, `ns.COMBO_DOT_SIZE`, `ns.ComboDotOffset(i)` (ComboPoints.lua): for things placed around combo dots.
- `ns.swingRing` (Swing.lua): the swing Cooldown. Cast.lua sets its alpha to 0 while casting, so it keeps timing underneath.
- `ns.IsClearcasting()` (Proc.lua): true/false, or nil if unknown (in combat without Omen of Clarity tracked in the Cooldown Manager).
- `ns.IsCasting()` and `ns.OnCastChanged(callback)` (Cast.lua): whether our cast ring and text are showing, and a callback when that changes. Unused for now (ShiftOrbs.lua used it to hide its orbs under the cast text, before the text moved below them).
- `ns.CDM.IsActive(spellID)`, `ns.CDM.OnChange(fn)` (CooldownManager.lua).

## Patterns to reuse

- **Showing a secret number**: pass it straight to `StatusBar:SetValue`/`SetMinMaxValues` or `FontString:SetText`/`string.format`. Never compare or do math on it.
- **Showing an aura in combat** (buff on player, debuff on target): `ns.CreateAuraContainer`. Blizzard shows a button while the aura is up; our look goes on the button in `initialize` and must be static after that (the button and its children are off-limits to our code later). For a timer, create a `Cooldown` in `initialize` and register it with `button:SetDurationCooldown(cooldown)`: Blizzard drives it with the real duration. Examples: `Proc.lua` (static cap), `DotRings.lua` (timer rings).
- **Filling a round shape from the bottom**: a vertical `StatusBar` with a flat or baked-gradient texture, masked (`CreateMaskTexture` + `AddMaskTexture`) to a circle or ring. Example: `Resource.lua`.
- **Arcs growing along a ring from any point** (a Cooldown swipe always starts at 12 o'clock): per side, a clip frame (`SetClipsChildren(true)`) showing half the ring, holding a half-ring texture that `SetRotation` swings into view. Examples: `FiveSecondRule.lua` (two arcs anchored at 6 o'clock, shrinking from 12), `Cast.lua`.
- **Showing something depending on a secret number** (e.g. "how many casts can my mana pay for"): one pre-built variant per outcome, each with alpha from a step curve evaluated engine-side (`UnitPowerPercent(unit, powerType, false, curve)`, curve x is the fraction of max) that's 1 only in that outcome's range. Example: `ShiftOrbs.lua` (centred rows of 1-5 orbs). If the thing already animates its own alpha, put the curve on a parent frame instead (effective alpha multiplies), like ShiftingPower.lua's pulse gate.
- **Filling a fixed, coloured arc of any shape** (colour baked by position, so the art can't rotate): the coloured art stays put, masked (`AddMaskTexture`) by `half_plane`, and the *mask* is rotated with `SetRotation` so its edge sits at the fill front. Only the filled part shows; the rest is empty. Works for arcs spanning under 180 degrees; for more (a full ring), split it into segments, each a wedge from two masks: `ns.CreateSegmentedArc` (SegmentedArc.lua) does this. Examples: `ShiftingPower.lua`, `GrowlArc.lua`, `CooldownRings.lua` (untested in-game: two masks on one texture, and one mask shared by several textures).
- **Resizing a frame from a corner**: `StartSizing` misbehaved on the settings window (jerky, then jumped to the maximum height; 2026-10-02), even after anchoring by the opposite corner. `Options.lua` now does its own drag: pin the top-left corner, then each frame set the size to the size at the press plus the cursor's movement (in the frame's scale), clamped to the screen. The cooldown box's corner grips (`Cooldowns.lua`) still use `StartSizing` and may need the same.
- **Resizing something built from AuraContainer buttons**: build at a fixed size and `SetScale` the frame they live in; the buttons themselves are forbidden after setup. Example: `Cooldowns.lua`.
- **Moving decoration on an AuraContainer button**: a looping animation started once with `Play()` at setup (no `OnShow`/`OnHide` handlers: blocked on these buttons). For motion a rotation can't do (dashes running around a square), a `FlipBook` animation over a grid of pre-drawn frames. Example: `Cooldowns.lua` (`square_dashed`).
- **Timer rings**: a `Cooldown` frame with `SetSwipeTexture(<ring texture>)`, `SetDrawEdge(false)`, `SetDrawBling(false)`, `SetHideCountdownNumbers(true)`. Starts full and empties clockwise. Plain-number timings go to `SetCooldown`; secret ones need a duration object (`SetCooldownFromDurationObject`).

## Debugging and testing

The user tests in-game; Claude can't run the game. Each change ends with exact steps and what to look for.

- `/catnip debug` toggles grey debug lines (saved). Modules print startup facts, e.g. which detection method is active.
- `/catnip perf start [label]`, play (in and out of combat), `/catnip perf stop`: prints the top 15 rows of time spent in Catnip's code (ms per second of play, in combat and out, calls, average and worst call) and saves the full report in `CatnipDB.perfReports`. Plain `/catnip perf` shows the report so far while measuring. For before/after comparisons, run the same activity under two labels. Times are inclusive (a handler that calls another module's callback counts its time), and the shared factories count under their own file (every arc's clock is `SegmentedCooldown OnUpdate`). A new runtime `.lua` file needs the `ns.Profiled` line at its top to be timed.
- `/catnip cdm` lists what the Cooldown Manager is tracking and what's readable.
- `/catnip spells` lists every spellbook entry and why the Cooldowns tab offers it or not.
- `/catnip item <id or shift-clicked link>` shows an item's class/subclass, use spell, whether it counts as a potion, and its raw cooldown.
- `/catnip art` (typed with the mouse over a Blizzard window) records every texture in that window (debug name, layer, atlas or file ID, size, tex coords, colour) into `CatnipDB.artDump[<window>]`. After a `/reload`, read it from `_classic_beta_\WTF\Account\<account>\SavedVariables\Catnip.lua`. For reusing Blizzard's art.
- `/catnip icon` (typed with the mouse over an icon, e.g. in the macro icon picker) prints that icon's file ID with a preview, and keeps the last 10 in `CatnipDB.iconPicks`.
- Errors: BugSack is **not** installed in the Forever client (checked 2026-09-27); ask the user for the full error text.
- `/reload` picks up code, `.toc` file lists and textures, but **not a new `## SavedVariables` name** (probably needs a restart); keep new saved data inside `CatnipDB`.
- To verify an unknown API, add debug output that prints what the game actually returns (with `ns.Describe`, which shows `<secret>`), test in and out of combat, then record the result in api-research.md.

## Reference addons

Check these before general web searching, in this order:

1. **[EllesmereUI](https://github.com/EllesmereGaming/EllesmereUI)**: a large Midnight UI suite with many active contributors, now being adapted for Forever. The best source for current API usage. Search its code and pull requests: Forever-specific fixes land as PRs, e.g. the swing timer via `PLAYER_SWING` (PR #2150) and the Forever GCD fix (PR #2240).
2. **[Cooldown Manager Centered](https://www.curseforge.com/wow/addons/cooldown-manager-centered)** (CMC, by WilduTools): the most popular skin and extension for Blizzard's Cooldown Manager (6.8M downloads), with Retail and Forever (1.60.x) builds. The reference for styling and extending the built-in Cooldown Manager. There's no official repo; [andi-74/cooldownmanagercentered-mirror](https://github.com/andi-74/cooldownmanagercentered-mirror) is a third-party GitHub mirror (the addon zip is attached to each GitHub release, not in the repo; it covers Forever too, which its code calls "Camelot"), or download the Forever file from CurseForge.
3. **[Forever Cooldown Manager](https://www.curseforge.com/wow/addons/forever-cooldown-manager)** (by Thunderz96; source at [Thunderz96/ForeverCDM](https://github.com/Thunderz96/ForeverCDM)): a Forever-only replacement for the Cooldown Manager that builds cooldown and buff icon rows from the spellbook and the player's auras, with no libraries. Its description says Blizzard's Cooldown Manager "has no spells to show for most classes" on Forever yet, and that it stays within combat restrictions by giving hidden timing values directly to Blizzard's cooldown widget without reading them (unverified by us).
4. **Blood in the Water** (another Forever Feral addon), installed locally at `C:\Program Files (x86)\World of Warcraft\_classic_beta_\Interface\AddOns\BloodInTheWater\`. Its comments document many Forever quirks; it's where the AuraContainer technique came from.
5. **[EnhancedCooldownManager](https://github.com/argium/EnhancedCooldownManager)**: the Cooldown Manager reading technique.
6. **ForeverAuras** (a WeakAuras port for Forever, v0.70.34-BETA.1), installed locally at `_classic_beta_\Interface\AddOns\ForeverAuras\`. The reference for spell cooldowns under secrets (`SpellCooldown.lua`, `GenericTrigger.lua` around `secretPoller` and `InitCooldownReady`), engine-driven timers and text (`SecretAuraSingle.lua`, `DurationText.lua`, `ProgressTextureNative.lua`) and restriction-state tracking (`Secrets.lua`, `ClientAPI.lua`). What we learned is in [api-research.md](api-research.md#from-foreverauras-unverified-by-us).

## Releasing

1. Bump `## Version` in `Catnip.toc` (e.g. `0.1.0-beta.3`).
2. The user commits, pushes, then tags and pushes the tag: `git tag v0.1.0-beta.3`, `git push origin v0.1.0-beta.3`.
3. `.github/workflows/release.yml` builds `Catnip-<tag>.zip` (a `Catnip/` folder) and publishes it on the Releases page. Tags containing `-` become pre-releases. `.gitattributes` keeps dev files (`docs/`, `tools/`, every `.md` file including `README.md`, etc.) out of the zip. A second job runs the [BigWigsMods packager](https://github.com/BigWigsMods/packager) to upload the same tag to CurseForge: it needs the `CF_API_KEY` repository secret (a CurseForge API token) and `## X-Curse-Project-ID` in `Catnip.toc`, and is skipped while the secret is unset. Its ignore list is in `.pkgmeta`; keep it in step with `.gitattributes`. Tags containing `alpha` or `beta` upload as that release type.
4. Keep `README.md` (player-facing install and usage) in sync with features.
